第 1 部分　這個 App 是什麼
================================================================

名稱      Healthy Care
用途      第二型糖尿病預防的生活型態管理，繁體中文，個人使用
網址      https://fyj5867.github.io/Foodie-control/
程式碼    https://github.com/fyj5867/Foodie-control
本機位置  C:\Users\joyce_fan\Foodie-control

技術上是一個「純前端」的網頁 App（PWA）：
  - 沒有伺服器、沒有資料庫、沒有帳號
  - 所有健康資料只存在手機/電腦的瀏覽器裡（localStorage）
  - AI 拍照辨識是瀏覽器直接呼叫 Google Gemini 或 Anthropic Claude，
    API Key 由使用者自己填，只存在本機

目前的功能：
  總覽／個人資料／飲食建議／活動力／體態紀錄／健康分析 六個分頁
  拍照算熱量（一餐可拍多張加總、會分項列出、並檢查數字互相對不對得起來）、
  熱量標準值記憶、每一餐的健康影響
  三項每日達標（熱量<1500、運動30分、喝水2000cc）與植物養成花園
  健檢報告拍照辨識（45 項數值＋9 項定性）、每7天重點、每月分析
  就醫紀錄、回診提醒、建議檢查項目與科別
  自己排定檢查（可填醫院與醫師），一鍵加入手機行事曆（.ics）
  運動建議與 YouTube 影片、每週運動目標
  體重計拍照自動填入體態紀錄
  睡眠以「時／分」兩格填寫

第 2 部分　日常操作
================================================================

--- 2-1 打包 ---------------------------------------------------

只有一行要記：

    cd /d C:\Users\joyce_fan\Foodie-control\source && npm run rebuild

它會依序做完：跑測試 → 打包 → 回報產出有沒有變、多大。

看到這樣就是成功：
    17 / 17 個檔案通過
    app.bundle.js  991.1 KB
    產出已更新

（檔案數和大小會隨著功能增加而變，重點是「全部通過」和「產出已更新」）

「產出與上次相同」也是正常的，代表你沒有改到程式碼。

重要：測試沒過就不會打包。這是刻意的保護 ——
app.bundle.js 是真的被部署出去的檔案，從一份規則已經不成立的
程式碼打包出來，比打包失敗更糟。


--- 2-2 怎麼開終端機（Windows） -------------------------------

方法一（推薦，不會跑錯資料夾）：
  1. 按 Win + E 開檔案總管
  2. 最上面的網址列貼上：
     C:\Users\joyce_fan\Foodie-control\source
     按 Enter
  3. 網址列裡的路徑整段刪掉，改打三個字母 cmd，按 Enter
  4. 黑色視窗出現，而且已經在正確位置
  5. 打 npm run rebuild

方法二：
  開始選單搜尋「命令提示字元」，打開後貼上第 0 部分那一行。

判斷有沒有站對地方：
  黑色視窗左邊那串路徑，結尾必須是  \source>
  不是的話先打  cd source


--- 2-3 上線到手機 ---------------------------------------------

    cd /d C:\Users\joyce_fan\Foodie-control
    git add -A
    git commit -m "說明改了什麼"
    git push

推完 GitHub Pages 幾分鐘內自動更新。

手機上看不到更新的話：
  改版時要把 sw.js 裡的 CACHE_NAME 換一個新版本號
  （例如 healthy-care-v29 改成 v30），否則舊的離線快取會一直
  給舊畫面。換完之後手機上把 App 完全關掉再重開。


--- 2-4 換一台新電腦 -------------------------------------------

    winget install OpenJS.NodeJS.LTS
    （裝完把終端機關掉重開）

    git clone https://github.com/fyj5867/Foodie-control.git

    cd Foodie-control\source
    npm install
    npm run rebuild

npm install 只有第一次需要。

第 3 部分　出問題時
================================================================

問題：npm error / Could not read package.json
原因：位置差一層，你在 Foodie-control 而不是 Foodie-control\source
做法：打 cd source 再重來

問題：'npm' 不是內部或外部命令
原因：Node.js 沒裝，或裝完沒有重開終端機
做法：見 2-4，裝完務必把黑色視窗關掉重開

問題：測試沒過，所以沒有打包
原因：程式有地方壞了。這是保護機制，不是故障
做法：把黑色視窗上的訊息整段複製給 AI，它看得懂

問題：改完程式，但網站上沒變
原因：忘記重新打包，或忘記 push
做法：網站載入的是 app.bundle.js（打包產物），只 push 原始碼
      不會有任何改變。一定要先 npm run rebuild 再 push

問題：電腦上是新的，手機上還是舊的
原因：Service Worker 的離線快取
做法：換 sw.js 的 CACHE_NAME，重新打包並 push，
      手機把 App 完全關掉再重開

第 4 部分　交給另一個 AI 繼續開發
================================================================

把整個 Foodie-control 資料夾給它（或叫它 git clone），
然後把下面【框起來的整段】複製貼給它當第一句話。

┌─────────────── 從這裡開始複製 ───────────────┐

這是一個已經在運作的個人健康管理 PWA，我要繼續優化它。

請你先做這三件事，做完再開始動手：

1. 讀 CLAUDE.md。那是這個專案的規則書，記錄了每一個決定的理由，
   以及好幾個「不會報錯、只有測試抓得到」的坑。不要跳過。
2. 讀 REBUILD.md，了解怎麼打包與部署。
3. 執行 cd source && npm install && npm run rebuild，
   確認 17 項檢查全部通過再開始改。

改任何東西時，這幾條絕對不能違反：

* 不要改 localStorage 的鍵名。這些是找到手機上既有資料的唯一
  途徑：profile、body-records、food-log、water-log、
  exercise-log、daily-summary、food-calories、health-reports、
  workout-links、clinic-visits、exam-plans。改了不是換個名字，
  是把使用者所有紀錄變成孤兒。
  同樣不能改的還有「一筆紀錄裡的欄位名」，理由一樣。例如睡眠的
  輸入欄位在 2026-09 改成「時／分」兩格，但存進 body-records 的
  仍然是原本那個小數 sleepHours —— 換掉它會讓每一夜已經記過的
  資料讀不出來。

* 健康數值只有一個來源：source/lib/health.js。不要把常數或公式
  複製到別的檔案，兩份副本遲早各自漂移，而漂移的那份不會報錯，
  只會給出錯的健康建議。

* AI 不寫醫療文字。視覺模型只負責「看照片、回傳數字或標籤」，
  每一句使用者會讀到的健康說明都寫在程式裡並被測試檢查：
  不診斷、不預測數字會怎麼變、疾病只寫成族群層級的關聯、
  腎功能相關的異常完全不給飲食建議（那是醫師的決定）。

* 資料欄位名不能猜。讀錯欄位不會報錯，只會回傳 0，然後某個判定
  永遠不成立。這在這個專案真的發生過一次。

* 版面要用 320px 寬測，不是 375px。iPhone 開了「顯示縮放」之後
  回報的就是 320。改完版面請逐一比對每個元素和它父層的寬度。

* 改完程式一定要 npm run rebuild 再 push。網站載入的是打包產物
  app.bundle.js，只 push 原始碼不會改變網站上的任何東西。

* 改動要有對應的測試。這個專案有 1874 項斷言分在 16 個測試檔
  （加上 check-imports 共 16 項檢查），新增的測試檔會被自動掃到，
  不用去改 package.json。

我要改的是：（在這裡寫你要它做什麼）

└─────────────── 複製到這裡為止 ───────────────┘


--- 為什麼要這樣交接 -------------------------------------------

這個專案裡有好幾個問題是「畫面看起來正常、但其實壞掉」的類型，
例如：

  - 運動時間存的是 durationMin，判定卻讀 minutes，
    結果運動永遠無法達標，而測試因為用了同樣錯的名字所以全過
  - Number(null) 是 0，而 0 落在好幾個健檢項目的「正常」區間，
    所以沒量到的欄位會被判成正常
  - 匯出備份的欄位清單和還原的清單各寫各的，
    結果某一項加進了還原，實際下載到的檔案裡卻沒有

這些都不會報錯。新的 AI 如果沒讀 CLAUDE.md 就直接改，
很容易重新製造同一類問題。所以「先讀規則書」不是客套話。

第 5 部分　檔案在哪
================================================================

Foodie-control\
  SOP.txt              這一份
  REBUILD.md           怎麼重新產出這個 App（獨立完整的一頁）
  CLAUDE.md            規則書：每個決定的理由、每個踩過的坑
  README.md            給使用者看的：API Key 怎麼設、怎麼加到主畫面

  index.html           網頁外殼
  app.bundle.js        打包產物 —— 不要手改，它是編譯出來的
  manifest.json        PWA 設定
  sw.js                離線快取（改版記得換 CACHE_NAME）
  icon-*.png           App 圖示

  source\App.jsx       主畫面與狀態
  source\lib\          規則與資料處理
  source\components\   畫面元件
  source\tools\        測試與工具

source\tools\ 裡面：
  build-all.mjs        npm run rebuild 跑的就是它
  run-tests.mjs        掃出並跑完所有測試（npm test）
  check-imports.mjs    找出「用了但忘記 import」的名字
  test-*.mjs           各項規則的測試，共 16 個檔案（1874 項斷言）
  serve.mjs            本機伺服器
  gen-sprout.mjs       從設計稿產生植物的圖
  import-quotes.mjs    從真乘心語的 .docx 重新匯入句子
  preview-*.jsx        一次看全部狀態，用來判斷畫面好不好

第 6 部分　備份你的健康資料
================================================================

程式碼在 GitHub 上有備份，但你手機裡的健康紀錄沒有。

在 App 的「個人資料」頁最下方有「匯出資料」，會產生一個 JSON 檔，
可以存到 Google Drive 或 iCloud。裡面包含：
  個人資料、體態紀錄、飲食紀錄、喝水、運動、每日達標、
  熱量標準值、健檢報告、就醫紀錄、排定的檢查、運動影片連結

換手機或清掉瀏覽器資料之前，記得先匯出。
同一頁也有「匯入資料」可以還原。
