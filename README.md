# 糖前哨 — 獨立網頁版

這是一個完全獨立、不需要 Claude 帳號登入即可使用的靜態網頁 App。所有健康資料只存在
使用者自己的瀏覽器裡（localStorage），不會上傳到任何伺服器。

## 這個資料夾裡有什麼

```
index.html      網頁主檔案
app.bundle.js   打包好的 App 程式（React + 圖表庫都已包在裡面）
manifest.json   PWA 設定檔，讓 iPhone「加入主畫面」時有獨立圖示與全螢幕體驗
sw.js           離線快取（App 外殼可離線開啟，但拍照分析仍需要網路）
icon-*.png      App 圖示
source/         原始 React 原始碼，之後想修改功能可以從這裡改，改完重新打包
```

## 第一步：設定「拍照分析熱量」用的 AI 服務

「拍照分析熱量」功能需要呼叫一個 AI 視覺服務。App 現在支援兩種，可以在「個人資料」頁
最下方切換：

### 選項 A：Google Gemini（推薦，真的免費、不用信用卡）

1. 前往 https://aistudio.google.com/app/apikey
2. 用 Google 帳號登入
3. 點「Create API Key」建立一組金鑰並複製
4. 回到 App「個人資料」頁 → 「AI 拍照分析設定」→ 選「Google Gemini（免費）」→ 貼上金鑰 → 「儲存金鑰」

免費額度有速率限制（每分鐘/每天的次數上限），一般人一天拍幾張食物照片完全用不完。
需要注意：免費額度的請求內容，Google 有可能會用來改善他們的產品（付費方案則不會），
如果介意這點，可以改用下面的付費方案。

如果之後 App 顯示「找不到模型」的錯誤，代表 Google 更新了模型名稱，可以到「進階：
自訂模型名稱」欄位，依照 https://ai.google.dev/gemini-api/docs/models 上的名稱更新
（目前預設值是 `gemini-3.6-flash`；Google 的模型改版頻率頗高，如果之後又失效，一樣
到官方頁面查最新可用名稱填進去即可，不需要重新打包 App）。

### 選項 B：Anthropic Claude（付費，需先加值）

1. 前往 https://console.anthropic.com/settings/keys
2. 註冊/登入，到 Billing 頁面綁定付款方式並儲值（建議同時設定每月用量上限）
3. 建立一組 API Key 並複製
4. 回到 App「個人資料」頁 → 「AI 拍照分析設定」→ 選「Anthropic Claude（付費）」→ 貼上金鑰 → 「儲存金鑰」

分析一張照片大概不到 1 美分，一般使用量每月大概 1-2 美元以內。

兩種金鑰都只會儲存在你自己這台裝置的瀏覽器裡，不會上傳到任何伺服器，也不會互相影響
——你可以兩組都設定起來，之後隨時在設定裡切換使用哪一個。

## 第二步：把這個資料夾放到網路上

你需要一個地方「主機」這些檔案，讓手機可以透過網址打開。以下兩個都是免費、幾分鐘
可以完成、不需要寫程式的方式：

### 方法 A：Netlify Drop（最簡單）
1. 瀏覽器打開 https://app.netlify.com/drop
2. 直接把這整個資料夾拖曳到網頁上
3. 幾秒後會產生一個網址（例如 `https://xxxx.netlify.app`），這就是你的網頁連結
4. 需要一個免費 Netlify 帳號才能長期保留這個網址（不然是暫時的）

### 方法 B：GitHub Pages
1. 在 https://github.com 建立一個新的 repository（設為 Public）
2. 把這個資料夾裡的所有檔案上傳上去
3. 到 repository 的 Settings → Pages，Source 選擇你剛剛的分支（通常是 main）
4. 幾分鐘後會有一個 `https://你的帳號.github.io/repo名稱/` 網址

兩種方法都可以，選你比較熟悉的即可。

## 第三步：在 iPhone 上「安裝」成 App

1. 用 iPhone 的 **Safari** 打開你上一步拿到的網址（一定要用 Safari，其他瀏覽器
   沒有「加入主畫面」功能）
2. 點下方的「分享」圖示（方框加箭頭）
3. 選擇「加入主畫面」
4. 主畫面就會出現「糖前哨」的 App 圖示，點下去會全螢幕開啟，沒有 Safari 網址列，
   體驗上很接近原生 App

## 之後想修改功能？

`source/` 資料夾裡是完整的 React 原始碼。修改 `source/App.jsx` 之後，需要重新
打包成 `app.bundle.js`：

```bash
cd source
npm install react react-dom recharts lucide-react
npx esbuild entry.jsx --bundle --minify --loader:.jsx=jsx --format=iife \
  --define:process.env.NODE_ENV='"production"' --outfile=../app.bundle.js
```

打包完成後，把新的 `app.bundle.js` 覆蓋原本的檔案，重新上傳到你的主機即可。

## 這次新增的功能

- **喝水量提醒與紀錄**（總覽頁新卡片）：依照個人資料（性別、體重、活動量）估算今日
  建議飲水量，可愛的水滴角色會依達成率變換表情（想睡→普通→開心→慶祝灑花），一鍵
  快速記錄常見份量（一杯200ml／一瓶350ml／一大瓶600ml），也可以自訂毫升數，並列出
  今天已記錄的每一筆。若有腎臟疾病、心臟衰竭等需限制水分的情況，App 會提醒改依醫師
  指示，不套用試算值。
- **運動紀錄與達成率**（運動建議頁）：可以勾選或自訂運動內容（快走、慢跑、游泳、
  騎車、羽球、肌耐力、伸展等）並填寫時間，App 會累積近7天的運動分鐘數，跟每週150
  分鐘的建議目標比較，顯示達成率、進度條、分類統計（有氧/阻力/柔軟度各做了幾次），
  並依情況給出建議（例如「還差多少分鐘」「本週還沒安排阻力訓練」）。
- **飲食紀錄可直接編輯熱量**：飲食紀錄列表裡，每一筆的熱量數字改成可以直接
  點擊修改的欄位，改完離開該欄位就會自動存檔，不用刪除重加。
- **今日熱量／喝水量都標注計算方式**：兩張卡片都新增「這個目標怎麼算出來的？」可展開
  區塊，清楚列出用了哪些數值、公式怎麼算的。
- **體態紀錄（如 OMRON 量測值）連動每日計算**：「今日熱量」的基礎代謝率、「今日喝水
  量」的體重基準，都會優先使用你在「體態紀錄」填的最新一筆數值，並在展開區塊裡註明
  是取自哪一天的紀錄；如果還沒有體態紀錄，才會退回用「個人資料」裡的固定數值或公式
  估算。BMI 顯示也會優先採用最新一筆體態紀錄的體重。
- **修正：飲食紀錄只能編輯「今天」的問題**：之前「可編輯熱量」只出現在今天的紀錄裡，
  昨天以前拍的東西完全看不到、也編輯不到。現在改成顯示「最近7天」的所有紀錄（不分是
  哪一天），每一筆都能直接編輯熱量、看得到日期，並在旁邊加了 ✏️ 圖示提示這裡可以點擊
  修改。
- **拍照辨識優先讀取包裝營養標示**：如果照片中有拍到包裝食品的營養標示文字，AI 現在
  會優先讀取標示上印的實際數字，而不是純粹用外觀猜份量，準確度會提升很多；如果沒拍
  到標示、只能用外觀估算，AI 也會更誠實地把信心程度標低，提醒你自行核對調整。

- **飲食紀錄顯示照片**：拍照分析後加入紀錄的項目，「今日飲食紀錄」列表會顯示縮圖
  （手動輸入的項目沒有照片，會顯示一個灰色圖示佔位）。照片會自動壓縮成小縮圖再儲存，
  避免佔用太多裝置空間；飲食紀錄的保留天數也從60天調整為30天，讓總容量更有餘裕。
- **體態紀錄分項趨勢圖**：「體態紀錄」頁現在會分別顯示體重、BMI、體脂肪率、骨骼肌率
  四張獨立的趨勢圖（至少要有2筆對應數值才會顯示該張圖）。
- **匯出備份可直接存到 Google Drive**：點「匯出備份」會優先跳出手機內建的分享選單
  （不是直接下載），選單裡可以選「儲存至 Google Drive」（如果手機上有裝 Google Drive
  App）、iCloud 雲端硬碟，或其他你安裝的雲端空間 App。如果裝置不支援分享選單，會自動
  改回原本直接下載的方式。



## 資料備份，避免任何原因造成資料不見

App 現在「個人資料」頁多了「資料備份」區塊，可以：
- **匯出備份**：把個人資料、體態紀錄、飲食紀錄打包成一個 `.json` 檔案，優先跳出分享
  選單讓你選擇存到 Google Drive、iCloud 雲端硬碟等地方（裝置不支援分享選單時會改回
  直接下載）
- **匯入備份**：選擇之前匯出的 `.json` 檔案，把資料還原回來

建議偶爾（例如每次更新完 App 之後）匯出一次存起來，這樣不管未來是清除瀏覽器資料、
換手機、換瀏覽器，都能用備份檔案救回。

**小提醒（重要，先講清楚避免誤會）**：單純把新版 `app.bundle.js` 上傳覆蓋到 GitHub、
更新網頁本身，**完全不會**清掉你手機上已經存的資料——網頁檔案跟瀏覽器裡存的資料是
兩件獨立的事。真正會清掉資料的，是類似「清除 Safari 網站資料」這種操作，才會需要用
備份檔案救回。

## 每天記錄更快一點：App 會記住你上次停在哪一頁

現在 App 會自動記住你上次瀏覽的頁籤，下次打開時直接顯示同一頁，不用每次重新切換。
如果你習慣天天在「體態紀錄」頁輸入資料，只要上次是停在那一頁，之後每次點主畫面圖示
就會直接看到輸入表單，省下切頁籤的步驟。

## 關於「網址參數自動記錄」功能（已移除）

早期版本曾經提供透過網址參數（`?wt=...&bf=...`）搭配 iOS 捷徑自動記錄體態資料的功能，
方便串接 Apple 健康。這個功能已經移除——它是目前唯一一個「打開頁面就可能自動寫入資料」
的機制，考量到多數人不會用到，但風險（例如不小心用舊網址、舊主畫面捷徑打開，寫入非
預期的資料）大於好處，所以拿掉了。現在整個 App 裡，任何會寫入或清除資料的動作，都必須
是你在畫面上主動點按鈕才會發生，不會有「打開頁面就自動變更資料」的情況。

如果之後還是想要類似的自動化，建議改用「資料備份」的匯出/匯入功能搭配手動操作，會更
可控、不會有意外覆蓋資料的風險。

## 內容多久更新一次？

飲食紅綠燈與運動建議的內容不會自動更新（這是純靜態網頁，沒有伺服器可以定期爬官方
網站）。App 裡「飲食建議」「運動建議」頁最下方都加了「資料來源與最後校對日期」，
標明目前內容是根據哪些官方資料、什麼時候校對的。

之後想更新的時候，直接回來這個對話跟 Claude 說「幫我校對更新飲食/運動建議的內容」，
我會搜尋最新的官方資料（衛福部國健署、糖尿病學會等）比對現有內容，有需要修改的地方
會直接改進 `source/App.jsx` 並更新最後校對日期，你只要把新的 `app.bundle.js` 覆蓋
上傳到 GitHub 就好。

## 重要提醒


本 App 提供的飲食、運動、熱量建議僅供健康生活型態參考，不是醫療診斷。拍照熱量估
算為 AI 粗略推測，實際數值可能有落差。如有實際血糖異常、已確診糖尿病或糖尿病前
期、或正在接受飲食相關治療，請務必諮詢醫師或營養師，不要完全依賴本 App 的估算數
字做健康決策。
